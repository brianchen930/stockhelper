## K 棒與成交量比對

官方歷史文件規定：分 K 時戳是起始時間且含時區；上市櫃整股分 K 成交量單位為「張」，日 K 為「股」。工具保留來源時戳、原成交量與單位，轉為 `Asia/Taipei` 及股數供比對。日 K 包含其他交易時段／類別，不能要求日成交量等於盤中分 K 加總。來源同上方[歷史 K 線文件](https://developer.fugle.tw/docs/data/http-api/historical/candles/)。

文件另載 13:25～13:30 為收盤集合競價，收盤成交自成 13:30 棒。這是明確的驗證風險；**不能僅看到 `timeframe=60` 就認定可直接接入現有五棒格式**。現有格式每日為 09、10、11、12、13 時起始，末棒在 13:30 完成。工具保留原生 13:30 棒；若多出一棒，完整覆蓋檢查會報 `BAR_GRID_OR_CALENDAR_MISMATCH`，不丟棄、不直接合併。

## 完整一年與暖身

沿用目前 `data_window` 推導，沒有重新設計暖身規則：

- 指定交易期間：2025-10-30～2026-10-29，共 241 個已列入日曆的交易日。
- 60 分 K：自 2025-10-13 09:00 起，含 60 根暖身與 1,205 根期間 K 棒，共需 **1,265 根有效標準棒／股票**。
- 日 K：自 2025-05-08 起，含 120 日暖身，共需 **361 個有效日收盤／股票**。
- 完整下載規劃每檔股票 3 次分 K、3 次日 K，共 12 次請求。小範圍查詢全數成功後，`--full-range` 才會執行。

下載成功不等於驗證成功。工具仍會檢查整個預期網格、重複／額外時戳、真實日曆衝突、日線暖身缺漏，並呼叫既有 `prepare_data` 驗證。真正缺漏保持失敗／UNKNOWN 的既有語意；不補價、不截短期間、不使用日 K 代替分 K。即使覆蓋通過，狀態仍要求人工審閱跨來源差異，工具本身不執行回測。

## 操作

於 `台股` 目錄，在同一個 PowerShell 視窗設定環境變數後執行。用隱藏輸入，避免把金鑰寫入命令歷史；不要把真實金鑰加入檔案或版本控制。

```powershell
$fugleSecureKey = Read-Host 'Fugle v1 行情 API Key' -AsSecureString
$env:FUGLE_API_KEY = [System.Net.NetworkCredential]::new('', $fugleSecureKey).Password

# 小範圍缺漏／正常日期比對
python -B -X utf8 -m 666_strategy.verification.verify_fugle_history --output 666_strategy/verification/fugle_live_probes.json

# 小範圍查詢成功後，進一步驗證一年與暖身
python -B -X utf8 -m 666_strategy.verification.verify_fugle_history --full-range --output 666_strategy/verification/fugle_live_full.json
```

必要時可提供 `--ca-bundle` 指向可信任 PEM 憑證。TLS 驗證不會被關閉。缺金鑰或驗證失敗會以非零狀態結束；報告不會列出假行情或假績效。
